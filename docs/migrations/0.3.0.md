# Migrating to 0.3.0

Version 0.3.0 moves every CodeScene contact into the push-to-`main` publisher,
`coverage-main.yml`, and removes the `codescene_project_id` Copier prompt. Pull
requests keep measuring coverage for their own ratchet but never receive the
CodeScene token or contact CodeScene.

## Update an existing project

1. Commit or otherwise preserve local changes before updating.
2. Run `copier update` using the same answers file and template source as the
   existing project. The answers file may still carry `codescene_project_id`;
   Copier ignores an answer the template no longer asks for, and the entry can
   be deleted.
3. Accept the new `coverage-main.yml`. Its
   `Check CodeScene token availability` step runs exactly
   `echo "available=${{ secrets.CS_ACCESS_TOKEN != '' }}" >> "$GITHUB_OUTPUT"`,
   the upload runs only when that output is `true` and `github.ref` is
   `refs/heads/main`, the token is passed only as the action's `access-token`
   input, and runs share the concurrency group
   `coverage-main-${{ github.ref }}` without cancelling one another. The upload
   no longer passes `installer-checksum`, so the `CODESCENE_CLI_SHA256`
   repository variable and any workflow that refreshed it can be removed.
4. Accept the `ci.yml` changes: the commented-out `mode: check` block and the
   full-history checkout that existed only for it are gone, and the coverage
   step runs at the publisher's `generate-coverage` revision with
   `publish-artefact: 'false'`.
5. If the project copied the commented `mode: check` step into a live step,
   delete it: pull requests must not reach CodeScene.
6. Run the generated project's full quality gates after resolving Copier
   conflicts.

The upload skips cleanly until the repository has a `CS_ACCESS_TOKEN` secret.
