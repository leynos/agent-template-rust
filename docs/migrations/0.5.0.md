# Migrating to 0.5.0

Version 0.5.0 ports the reusable build, validation and delivery tooling from
Catnap. Generated projects gain build-tool installers and read-only preflight
checks, strict YAML, workflow and shell lint gates, bounded test lanes, a
Markdown formatter, shared workflow contracts, and a release workflow that
builds every supported target. It does not introduce Netsuke, a Netsukefile or
Ninja; the Makefile remains the build entry point.

## Update an existing project

1. Commit or otherwise preserve local changes before updating.
2. Run `copier update` using the same answers file and template source as the
   existing project. Accept the new `github_repository` answer, or the value
   derived from `repository_url`, because the CV-005 configuration and the
   pull-request automation callers render it.
3. Provision the developers' tools. `make install-build-tools` installs the
   pinned Rust toolchain and its components, and installs `mold` on Linux.
   `make install-cranelift` installs the Cranelift backend on its own. The
   `check-build-tools`, `check-rust-toolchain` and `check-coverage-tools`
   targets only report what is missing; they never install anything, so run
   them in CI and on a fresh machine to see what a checkout needs.
4. Accept the rewritten `.cargo/config.toml`. Development flags are carried by
   `rustflags`, so remove any `[unstable] codegen-backend = true` entry and any
   `[profile.dev] codegen-backend` key. On Linux, the single
   `[target.'cfg(target_os = "linux")']` table selects `clang` and the `mold`
   linker alongside the development flags, which replaces the former per-triple
   linker table. Remove any local copy of those tables rather than keeping both.
5. Accept the new test lanes. `make all` now runs
   `check-fmt lint test test-ui test-workflow-contracts`. `make test` uses
   nextest's bounded `default` profile, and `make test-ui` runs compile-time
   contracts in `tests/compile_*.rs` under the serialized `ui` profile. The
   hosted coverage job keeps the same nextest profile but deselects the
   compile-time binaries with `scripts/exclude-ui-targets.sh`; do not move or
   rename those sources, and keep any explicit `[[test]]` declaration pointing
   at the file it names.
6. Replace `mdformat-all` with the `mdtablefix` route. `make fmt` and
   `make check-fmt` format and verify Markdown through `mdtablefix`, and CI
   installs the formatter at a pinned commit. Remove the former nightly
   formatter from local scripts.
7. Review the release workflow before the next tag. A `workflow_dispatch`
   builds every matrix leg and uploads its artefacts as a dry run by default,
   and a release is published only for a tag ref with the dry run turned off or
   for a tag push. Application releases build the macOS targets natively and
   the Linux, Windows and FreeBSD targets through the pinned `cross` revision.
   A Polonius project releases on the nightly pinned in `rust-toolchain.toml`
   with `-Zpolonius=next`, and clears the other development flags.
8. Add the coverage backstop. `coverage-main.yml` now accepts
   `workflow_dispatch` because a merge performed with `GITHUB_TOKEN` fires no
   push event, and `coverage-backstop.yml` dispatches it daily for a merge path
   that still fails to dispatch. Restrict the `codescene` environment to
   `main`, so a branch dispatch is refused before the upload job runs.
9. Add `.github/cv005.toml` and keep it in step with the `github_repository`
   answer. `make test-workflow-contracts` checks the rendered workflows against
   the shared contracts, and `make lint-yaml`, `make lint-actions` and
   `make lint-shell` run the strict YAML, workflow and shell gates.
10. Run the generated project's full quality gates after resolving Copier
    conflicts.

The generated project still requires `yamllint`, `actionlint`, `shellcheck` and
`mdtablefix` to be available to the commands that use them; the checks report a
missing tool rather than installing one.
