# Migration guide: v0.4.0 to v0.5.0

## Who should read this

Projects generated from the 0.4.0 template that are moving to 0.5.0. The
template now ships Catnap's reusable build, validation and delivery tooling:
build-tool installers and read-only checks, strict YAML, workflow and shell
lint gates, bounded test lanes, a Markdown formatter, shared workflow
contracts, and a release workflow that builds every supported target.

Crate source, package metadata and the Makefile entry point do not change. What
changes is how a checkout provisions its tools, how tests are separated, how
Markdown is formatted, and how a release is published. The template still
introduces no Netsuke, Netsukefile or Ninja.

## Impact at a glance

| Priority                        | Area                       | What to do                                           |
| ------------------------------- | -------------------------- | ---------------------------------------------------- |
| Required                        | Build tools                | Install the pinned toolchain, Cranelift and `mold`   |
| Required                        | CI tool installation       | Install `rust-analyzer`, drop local Whitaker scripts |
| Required                        | Cargo configuration        | Move development flags into `rustflags`              |
| Required                        | Test lanes                 | Accept the bounded profile and the `test-ui` lane    |
| Required                        | Markdown formatting        | Replace the nightly formatter with `mdtablefix`      |
| Required                        | Workflow contracts         | Add `.github/cv005.toml` and run the contract gate   |
| Review                          | Dependency updates         | Review the daily schedule, cooldowns and grouping    |
| Required if application flavour | Release workflow           | Adopt dry-run dispatch and tag-only publication      |
| Review if enabled               | CodeScene coverage         | Add the backstop and restrict the environment        |
| Optional                        | `github_repository` answer | Accept it when the callers need a name               |

_Table 1: Obligations when moving from 0.4.0 to 0.5.0._

## 1. Provision the build tools

Run `make install-build-tools`, which installs the pinned Rust toolchain and
its components and installs the pinned `mold` release on Linux.
`make install-cranelift` installs the Cranelift backend on its own.

The `check-build-tools`, `check-rust-toolchain` and `check-coverage-tools`
targets only report what is missing. They never install anything, so run them
in CI and on a fresh machine to see what a checkout needs.

## 2. Update the CI tool installation

Generated CI now adds the `rust-analyzer` component with
`rustup component add rust-analyzer` after the pinned toolchain is available,
so editors and analysis tools use the same compiler as the build. Add the step
to your own CI if it installs components separately.

CI also installs Whitaker through the shared `leynos/shared-actions`
`install-whitaker` action instead of a project-local installer. Remove any
local Whitaker cache, download, or installer script from the workflow and from
repository tooling, and pass the shared action's inputs from the workflow
instead. The Makefile still resolves `whitaker` from `PATH`, so no local binary
is required.

## 3. Rewrite the Cargo configuration

The development flags now live in `rustflags`; the profile and unstable keys
that carried Cranelift are gone. Remove the old keys rather than keeping both
shapes.

### Before

```toml
[unstable]
codegen-backend = true

[profile.dev]
codegen-backend = "cranelift"
```

### After

```toml
[target.'cfg(target_os = "linux")']
linker = "clang"
rustflags = [
  "-Zpolonius=next",
  "-Zthreads=8",
  "-Zcodegen-backend=cranelift",
  "-Clink-arg=-fuse-ld=mold",
]
```

A project without Polonius omits `-Zpolonius=next`. The single
`[target.'cfg(target_os = "linux")']` table replaces the former per-triple
linker table, so every Linux target that receives the `mold` flag also selects
the driver that accepts it.

## 4. Accept the test lanes

`make all` now runs `check-fmt lint test test-ui test-workflow-contracts`.
`make test` uses nextest's bounded `default` profile, and `make test-ui` runs
compile-time contracts in `tests/compile_*.rs` under the serialized `ui`
profile. Keep any explicit `[[test]]` declaration pointing at the file it names.

The hosted coverage job keeps the same nextest profile and deselects the
compile-time binaries with `scripts/exclude-ui-targets.sh`, because the shared
coverage action accepts no filter argument. Do not move or rename those sources.

## 5. Replace the Markdown formatter

`make fmt` and `make check-fmt` now format and verify Markdown through
`mdtablefix`, and CI installs the formatter at a pinned commit. Remove the
former nightly `mdformat` route from local scripts.

## 6. Add the workflow contracts

Add `.github/cv005.toml` and keep it in step with the `github_repository`
answer. `make test-workflow-contracts` checks the rendered workflows against
the shared CV-005 contracts, and `make lint-yaml`, `make lint-actions` and
`make lint-shell` run the strict YAML, workflow and shell gates.

## 7. Review the release workflow

This step applies to application projects only; a library render has no release
workflow.

A `workflow_dispatch` builds every matrix leg and uploads its artefacts as a
dry run by default, and a release is published only for a tag ref with the dry
run turned off or for a tag push. The macOS targets build natively and the
Linux, Windows and FreeBSD targets build through the pinned `cross` revision. A
Polonius project releases on the nightly pinned in `rust-toolchain.toml` with
`-Zpolonius=next`, and clears the other development flags.

## 8. Review the Dependabot policy

`.github/dependabot.yml` now checks GitHub Actions, Cargo dependencies and the
pinned `rust-toolchain` file daily. Shared-action callers form one group;
routine GitHub Action minor and patch updates form another; Cargo and toolchain
minor and patch updates form further groups, while a Cargo major update stays
on its own pull request. Fresh releases cool down for seven days and Cargo
major updates for fourteen.

The file configures no `labels`. Dependabot then applies its default
`dependencies` and ecosystem labels, which a new repository gains
automatically; a custom list would replace those defaults and silently drop
labels the repository does not define.

Review these values before adopting the file: the `schedule.interval` of
`daily`, the cooldown of seven days (`default-days`) and fourteen days for
Cargo major updates (`semver-major-days`), the `open-pull-requests-limit` of
five, and the group patterns. Longer cooldowns delay security fixes as well as
routine updates, so tighten them in a repository that needs faster adoption.

## 9. Adopt the coverage backstop

This step applies only to projects that publish CodeScene coverage.

`coverage-main.yml` now accepts `workflow_dispatch` because a merge performed
with `GITHUB_TOKEN` fires no push event, and `coverage-backstop.yml` dispatches
it daily for a merge path that still fails to dispatch. Restrict the
`codescene` environment to `main`, so a branch dispatch is refused before the
upload job runs.

## What does not need to change

- Crate source, public items and package metadata.
- The Makefile as the build entry point; no generated project gains a
  Netsukefile or Ninja build.
- `-Zpolonius=next` for a project that enables Polonius. It stays in the Cargo
  configuration, the Makefile, coverage and the release workflow.
- Existing `[[test]]` declarations, whose files the coverage exclusion keeps
  in place.
- Any library project's absence of a release workflow.

## Migration checklist

- [ ] Run `make install-build-tools` and, on non-Linux hosts, the checks that
      report the tools this platform needs.
- [ ] Install the `rust-analyzer` component in CI and remove any local Whitaker
      installer or cache.
- [ ] Replace the old Cargo profile and unstable keys with the single Linux
      `rustflags` table.
- [ ] Accept the `all`, `test`, `test-ui` and `scripts/exclude-ui-targets.sh`
      changes.
- [ ] Switch Markdown formatting to `mdtablefix`.
- [ ] Add `.github/cv005.toml` and pass `make test-workflow-contracts`.
- [ ] Review the release dispatch model (applications only).
- [ ] Review the Dependabot schedule, cooldowns and grouping.
- [ ] Add the coverage backstop and restrict the `codescene` environment
      (CodeScene users only).
- [ ] Run the generated project's full quality gates after resolving Copier
      conflicts.

## Common errors and fixes

- **Error:** ``feature `codegen-backend` is required``
  - **Fix:** remove `codegen-backend` from `[unstable]` and
    `[profile.dev]`. Stable Cargo refuses to parse the manifest, and the flag
    now belongs in `rustflags`.
- **Error:** `error: operator didn't match any binary names`
  - **Fix:** do not add a `binary(compile_*)` filter to
    `.config/nextest.toml` when the project has no `tests/compile_*.rs`.
    nextest validates every profile's filter at configuration load, so the
    checked-in default profile stays unfiltered and
    `scripts/exclude-ui-targets.sh` adds the exclusion only when a target is
    discovered.
- **Error:** `mold not found on PATH (pinned <version>)`
  - **Fix:** run `make install-build-tools`. The check reports the missing
    tool and never installs it.
- **Error:** `checksum mismatch for <archive>; refusing to install`
  - **Fix:** discard the download and rerun `make install-build-tools`. The
    installer compares every archive against `tools/mold/SHA256SUMS` and
    refuses a mismatched or incompletely recorded release.
