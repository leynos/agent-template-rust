# Migrating to 0.4.0

Version 0.4.0 strengthens the contributor guidance rendered into `AGENTS.md`
and removes the host-specific tool inventory from it. The generated project now
states explicit planning, architecture, verification, testing, observability,
and documentation expectations. Tool availability is treated as a property of
the execution environment rather than the generated project.

## Update an existing project

1. Commit or otherwise preserve local changes before updating.
2. Run `copier update` using the same answers file and template source as the
   existing project.
3. Review the `AGENTS.md` changes as contributor guidance rather than generated
   code. Preserve project-specific local instructions, then adopt the
   contract-first planning, operational-boundary, proportionate-verification,
   and behavioural-testing guidance where it applies.
4. Remove the former "Additional tooling" inventory if the generated file still
   carries it. Record the tools the project still depends on beside the
   workflow, automation, or developer documentation that uses them, so
   availability stays discoverable.
5. Review the amendment and supersession guidance in
   `docs/documentation-style-guide.md`. Link accepted decisions from design
   documents, and record later changes by superseding the original record
   rather than rewriting it.
6. Run the generated project's full quality gates after resolving Copier
   conflicts.
